# SRVF Admin 后端追赶蓝图：v0.39 → v0.64（2026-08-01）

> **性质**：功能覆盖二期 + 新面 UX 方案。回应主诉「前端已经落后后端 API 很多；补齐时 UI/UX 要人性化，普通人能上手」。
> **方法**：后端 handoff（`../srvf-nest-api/docs/handoff/admin-web.md`，575 行全文精读）+ 后端源码/openapi.json 快照盘点 + 前端全站 43 页/所有 `src/api/srvf-*.ts` 逐函数盘点 + 26 项关键契约标记 grep 实证。
> **基线**：前端 main `e4e3a0e`（#126 函数式抽屉收官）≈ 后端 **v0.39** 适配水位（#98/#99，2026-07-17 re-baseline）；后端现为 **v0.64.0**（v0.40 于 2026-07-11 → v0.64 于 07-29，另有 main 未发版增量）。落差 = 25 个版本。
> **定位**：四部曲之四。`srvf-admin-vnext-blueprint.md`（已归档）管 v0.37 前功能覆盖；`srvf-ux-audit-2026-07.md`（已归档）管表层修复；`srvf-admin-ux-upgrade-blueprint.md` 管产品化（**U0~U4 已全部落地**，#82~#93）；本文管 **v0.40→v0.64 的契约追赶与新面 UX**。
> **权威源纪律**：本文一切端点/字段引自 handoff 与后端源码快照，**动手时逐端点对 live `/api/docs-json` 核字段**（AGENTS.md §0 冲突顺序第 1 条）；写本文时本地 `:3000` 未运行，未做 live 对账——每个 PR 的 preflight 必须补这一步。

## 0. 一句话结论（30 秒版）

产品化底子是好的（七组导航、工作台、作战室、授权向导、函数式抽屉都在），但**后端 7 月中旬以来发了 25 个版本：为管理面新增约 70 个操作，前端只接了其中 6 个**（账号闭环）。差距分四层，按危险度排：

1. **契约已破坏（P0 止血）**——对着已发版的 v0.64 后端，**现用面（本地联调环境）至少 5 处点开就炸/出错数据/流程断头**：活动发布 400（v0.50 起必填 body）、**活动永远无法完结**（v0.50 起考勤提交不再推进状态而前端没有完结按钮→参与核对等 completed 功能全部够不到）、招新「非大陆证件」列恒空（v0.42 改名）、紧急联系人**掩码回写会污染真实数据**（v0.42 掩码收紧）、发号预检跳过原因文案失效（v0.40）；另贡献规则表单疑似 400（`dailyCap` 下线，版本待哨兵确认）。
2. **权限底座换轨（P1）**——登录第三调仍用旧 `rbac/me/permissions`（只认 GLOBAL）。后端 v0.49 起队长/部长/组长/副职/分管的权限全部走「职务/分管派生」，**这些干部现在登录会看到一个空菜单**。不换轨，scoped 授权整条投资对干部不可用。
3. **纯新增能力（P2~P5 补齐）**——活动岗位（v0.55）/评价（v0.54）/GPS 打卡考勤草稿（v0.52）/参与核对与月报（v0.51）/候补（v0.53）/批量审批（v0.51）/审批后悔药（v0.40）/考勤终审撤回（v0.47）/保险审核（v0.59~0.61）/一键离队（v0.40+v0.62 预检）/招新增强（v0.41+）等一大批**已发版、前端零覆盖**的能力。
4. **两个带闸区（P6/P7，不动工）**——① P6 = v0.62「活动责任闭环」工作流（发布审核工作台/负责人协办/考勤退回重提）：端点已发版但 **rollout 未执行**（handoff 明示当前不做认领/人员配置/切换）；② P7 = **证书标准库**（含证书工作台、标准库管理、招新申报审核共 22 端点）：**只在后端 main、未进任何发版 tag，且处于 Release NO-GO**（第五轮独立评审未过、零种子标准——零标准时建证/审核必拒、选择器恒空）。两者方案冻结在本文，等各自信号再动工；但要立**哨兵**：本地后端一旦跑含标准库的 main，现有证书 tab 即刻破（四处契约破坏），届时 §11 的证书止血片并入 P0。

建议节奏：**P0 一口气止血 → P1 换权限底座 → P2~P5 按业务价值分批补齐 → P6/P7 等信号**。全程零新依赖，全部复用 srvf-kit + Re\* + Element Plus 现成件。

## 12. UX 总纲：补齐期十条（承接七条军规，本批新页逐条验收）

> 七条军规（任务优先/说队里的话/登录即待办/页面自解释/配置藏后面/危险有礼/一处一真相）继续全量生效；以下十条是本批补齐工作的加规。

1. **错误码全翻译**：本批引入的 40+ 新 BizCode（20031/20037/20122/20124/20126/21033/21035/22081~22083/26011/26012/26031/28045~28062/29030/29031/13016/15036/17030/17031/30101~30104/31013/32020+/34001+）全部进 `bizErrorMessage` 域词条，三段式「出了什么事/为什么/怎么办」；**禁止任何新按钮裸抛后端 message**。
2. **掩码即防回写**：凡出现掩码/null 敏感字段的编辑表单，一律走「hasPerms 镜像敏感码 → 无权字段禁用+提示 → 提交前剔除」三步范式（profile 首例、P0-S5 紧急联系人、P7 证书编号）。新表单评审必查这条。
3. **批量动作三段式**：预览（能预检的先预检）→ 执行 → 逐行结果（成功/失败/原因，失败行可单独重试）。先例：批量开号、公告导入；本批：批量审批；弹药已备未接线：批量建绑定（`role-bindings/batch`，死函数已封装）。**HTTP 200 永不等于全部成功**。
4. **危险动作说清单**：离队/完结/撤回终审/退号重开类，确认弹窗逐条列「将会发生什么」+「什么会保留」，而不是一句「确定吗」。
5. **并发冲突说人话**：`expectedVersion`/26011 类冲突 = 「信息刚被他人更新」→ 自动刷新 + 请用户基于新状态重试；绝不静默重试覆盖。
6. **敏感资源按需申请**：证据图/证件照 signed-URL 点击才取、TTL 内有效、不入任何本地存储、不进埋点；关闭即弃。
7. **状态机画在界面上**：新增状态（waitlisted 候补位次、returned 退回修改、expired 展示态、已收录待认定）一律进 `SrvfStatusTag` 字典映射 + `SrvfFlowSteps` 节点，未知值兜底「未知状态」不直出枚举。
8. **成本动作二次确认**：短信类已有范式（confirmed:false 预览→confirmed:true 执行）；未来任何计费/外发动作沿用。
9. **新词先进术语表**：本批新增术语见 §13，菜单/按钮/文案用表内词，不得直出后端名。
10. **块级权限缺失≠0**：dashboard 新块、options 静默裁剪（resolve-labels 少 type）等「无权即缺失」场景，UI 隐藏该块而不是渲染 0/空错。
