## 同一候选端到端路径

环境必须是获准的隔离验收环境或维护者签准的演练窗口。每步附时间、角色、请求 ID、脱敏活动/版本/批次锚与结果，失败停止后续，不拿另一套版本拼接。行级候选数据只能来自合成身份；生产验收需另行授权。

1. **锁定制品和测试身份。** 绑定前述 SHA/digest/OpenAPI；设置同组织负责人、一审、终审三人和入队申请人 M，再准备异组织有读码者 X 与非收件成员 Y。申请在正式账本读源下新建；使用两个不同北京自然日的已批准正向活动和明确的轮次截止，先把 M 正式贡献做到 4，再用本条主验收活动贡献 +1。确认没有已有达标通知。独立核对 500 身份/500 当前段/500 当前分配、2,500 物理切片、2,000 评价及其余 native 限制；同候选复用已完成的受限规模证据，没有则补获准隔离证据，超限样本必须拒绝且不截断、不拆单绕过。
2. **走新写，验证旧写被拒。** 按新链报名、签到签退，负责人封场、生成并送审。用具备原旧写权限且请求有效的合成身份向仍在的 `/api/admin/v1/activities/{activityId}/attendance-sheets` 发一次旧写；预期 410 及 `ACTIVITY_LEGACY_ATTENDANCE_WRITE_CLOSED`、旧数据无变化。若本批同时验 #1433，另用完整证据的两个分段验证合法合计可保存，超量在编辑和固化前被拒且无部分写；不把该负例放到原生分类口径。
3. **按指定版本审核，验证隔离。** 负责人送审后记录版本与证据锚；一审在工作台搜索并逐页读冻结结果。X 用同一 `activityId` 筛选看不到目标版本，直读同版本也不得返回数据；核对撤权与不可见响应按最终契约。分别用一审、终审完成审核（可先退回再重提，旧版仍可核对）。没有独立账号或只能盲审时不通过。
4. **观察正式入账边界。** 在已批准可暂停的隔离窗口停在已审核未 committed；Admin 不显示已入账，M 的 `/api/app/v1/me/team-join/applications/current` 仍是 4，本人 feed 无 A9。恢复实际批准的入账分工，记录批次 committed 与进度 5。不能用固定 sleep 猜测批次阶段；生产不为制造状态擅停 worker。
5. **本人实际收到一条。** M 在指定客户端本人 feed 看见 `recruitment` 达标站内信并可读详情；Y 在自己的 feed 和同通知详情不获该定向消息。关联账本、永久事实、意图、worker 投递与本人 HTTP/UI 回执；精确重放不新增意图。旧协议申请只保留 `history_pending`，不视为发送或可以补发。
6. **记录放行与止血。** 最终候选 `cutover:check --profile r5-limited500` 的 A 项必须通过，B/C 按实际签字和回执确认。现场顺序为停旧写并排空 → 维护者部署已审迁移及同版全套 → 维护者开闸 → 同版本 smoke 与稳定窗。10a/10b 记录实际可部署的结算只读配置与演练：新旧写均拒，读仍是 committed，不把回关 v1.1 当无损回退；任何混档、账本/读源不符或未知提交停止放行。
